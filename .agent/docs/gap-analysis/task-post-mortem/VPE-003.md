# Explorative Task Post-Mortem: VPE-003

> [!ABSTRACT] Core Concept
> Architectural post-mortem evaluating the implementation of the Vertex AI Client and Go resource-safety improvements in VerdiPitchEngine.

## 1. Current State Evaluation
We successfully implemented a testable, mockable Google Vertex AI client interface (`pkg/ai/client.go`) to integrate with the telemetry observation layer using Gemini 1.5 Pro. We also closed severe robustness gaps by implementing explicit checkups on `scanner.Err()` inside the core FFmpeg output processing, wrapping file descriptor closes within safe defer functions, and handling return errors on file removals.
The current client implementation, however, has hardcoded values in its default runner (`RunAgent`), limiting its operational flexibility without environment configs.

## 2. Pros and Cons
### Pros
- Mock wrapper interfaces (`client` and `generativeModel`) decoupled the Google SDK's network calls, achieving 83.9% unit test coverage.
- Restricting client authentication to file-based Service Account JSONs ensures we maintain zero-trust integrity, avoiding fallback to developer credentials.
- Explicit scanner error validation prevents hidden I/O truncation failures in FFmpeg subprocesses.

### Cons
- The Vertex AI Go SDK is officially deprecated by Google in favor of the unified `google.golang.org/genai` library, which triggers build warnings.
- Multiple dependency vulnerabilities (GO-2026-4971, GO-2026-4918) are present in standard libraries on Go version 1.26.2.

## 3. Alternative Solutions
- **Unified GenAI SDK:** We could have used `google.golang.org/genai` directly. We selected the Vertex AI package to align with legacy configurations elsewhere in the cortex, but it introduces a time-bound deprecation.
- **Environment Autodetect:** Using default credentials autodetect could have simplified the code structure but would have bypassed the zero-trust isolation constraints.

## 4. Brainstorming / Future Enhancements
1. **[VPE-027] Migration to Google GenAI Go SDK**: Update `pkg/ai` to utilize the new `google.golang.org/genai` SDK to resolve package deprecation warnings.
2. **[VPE-028] Dynamic Telemetry Credentials Configuration**: Refactor the client runner to pull parameters dynamically from environment variables (`VERTEX_PROJECT_ID`, `VERTEX_CREDENTIALS_PATH`).
3. **[VPE-029] Go Vulncheck Dependency Upgrades**: Upgrade standard library and HTTP transport modules (to Go 1.26.3 or newer) to eliminate vulnerabilities GO-2026-4971 and GO-2026-4918.
